# Все промокоды

Лабораторная работа №3. Каталог скидок и промокодов на Django и SQLite. Гость просматривает каталог, USER работает со своими обращениями, ADMIN обрабатывает обращения всех пользователей и управляет предложениями.

## Запуск на Windows

Понадобятся Python 3.10 или новее и Node.js. Из корня проекта выполните в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm.cmd ci
npm.cmd run build
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py loaddata demo
.\.venv\Scripts\python.exe manage.py seed_demo_accounts
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

На готовой базе ЛР №2 достаточно применить миграции и создать демонстрационные аккаунты. `loaddata demo` нужна для пустой базы и повторно записывает исходные предложения. Для пересборки SCSS используйте `npm.cmd run dev`.

Откройте [главную](http://127.0.0.1:8000/), [вход](http://127.0.0.1:8000/login.html) или [админ-панель](http://127.0.0.1:8000/admin/).

## Демонстрационные аккаунты

Команда `seed_demo_accounts` создаёт локальные аккаунты и печатает случайные пароли при первом запуске:

| Логин | Email | Роль |
| --- | --- | --- |
| `demo_user` | `demo-user@example.test` | USER |
| `demo_other` | `demo-other@example.test` | USER |
| `demo_admin` | `demo-admin@example.test` | ADMIN |

Оба USER получают по одному демонстрационному обращению. Повторный запуск команды сохраняет существующие пароли. Для смены пароля используйте `manage.py changepassword <логин>`.

## Сценарий защиты

1. Зарегистрируйте аккаунт. Попробуйте короткий пароль, несовпадающие пароли и повторяющийся email. После успешной регистрации войдите по логину или email. Покажите имя аккаунта в шапке и завершите сессию через «Выйти».
2. Под USER откройте `/offer/?id=1` и нажмите «Сообщить о проблеме». Заполните комментарий, откройте «Мои обращения», измените комментарий, затем удалите своё обращение.
3. Скопируйте адрес обращения первого USER и откройте под вторым USER. Для чужой записи сервер вернёт 404 на просмотр, редактирование и удаление. При прямом переходе USER на `/manage/` получит 403. Вход в `/admin/` требует ADMIN.
4. Под ADMIN откройте [список обращений](http://127.0.0.1:8000/admin/promos/report/). Покажите автора и предложение, поменяйте статус с «Новое» на «В работе» или «Рассмотрено». Под владельцем проверьте новый статус.
5. Покажите, как пароль хешируется через `UserCreationForm`, как Django хранит сессию и как сервер проверяет роль и владельца записи. SQL-запросы приложения формирует ORM Django.

Для проверки серверной логики запустите `.\.venv\Scripts\python.exe manage.py test`. Чтобы увидеть SQL в консоли, установите `$env:SHOW_SQL = '1'` перед запуском сервера.
