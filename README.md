# Все промокоды

Лабораторная работа №2. Каталог демонстрационных скидок на доставку еды и продуктов. Django получает предложения из SQLite. Страницы используют SCSS и JavaScript из ЛР №1.

## Запуск на Windows

Понадобятся Python 3.10 или новее и Node.js. В PowerShell из корня проекта выполните:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm.cmd ci
npm.cmd run build
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py loaddata demo
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

Откройте [главную](http://127.0.0.1:8000/) или [управление каталогом](http://127.0.0.1:8000/manage/). `loaddata demo` нужен при первом запуске на новой базе. Повторная загрузка восстанавливает демонстрационные записи с исходными идентификаторами. Для пересборки SCSS при изменениях запустите `npm.cmd run dev` в отдельном терминале.

Формы управления предназначены для локальной демонстрации. Вход, регистрация и роли подключаются в ЛР №3.

## База данных

- [ER-диаграмма каталога](docs/er-diagram.md).
- [SQL-схема SQLite](docs/schema.sql). Получена командой `manage.py sqlmigrate promos 0001`. Для запуска приложения используйте `migrate`.
- [Модели каталога](promos/models.py). Магазин связан с предложениями отношением один-ко-многим. В базе по умолчанию четыре магазина и восемь предложений.

## Показ на защите

Чтобы увидеть SQL, остановите сервер и запустите его с переменной окружения:

```powershell
$env:SHOW_SQL = '1'
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

1. Откройте каталог. Django выполнит `SELECT` и передаст данные карточек в шаблон.
2. Перейдите в «Управление каталогом» и откройте форму добавления. Оставьте обязательное поле пустым и отправьте форму. Django покажет ошибку рядом с полем и сохранит введённые значения.
3. Заполните магазин, тип, скидку, заголовок, условия, дату и код или ссылку. При успешном POST в терминале появится `INSERT`. Новое предложение откроется после перенаправления и будет видно в каталоге.
4. Откройте `/offer/?id=1` и `/offer/?id=999999`. Первый запрос покажет `SELECT` с условием по первичному ключу, второй вернёт HTTP 404.
5. Измените созданную запись. Покажите `UPDATE` и неизменившийся идентификатор. Пройдите подтверждение удаления и покажите `DELETE` после отправки формы.
6. Объясните, где Django читает GET и POST, как `OfferForm` и `Offer.clean()` валидируют данные и как внешний ключ связывает предложение с магазином.

## Структура

- `promos/` — модели, миграции, представления и серверная форма предложения.
- `accounts/` — заготовка модели пользователя для ЛР №3.
- `templates/` — страницы Django и общие части интерфейса.
- `scripts/`, `styles/`, `assets/` — скрипты, стили и изображения.
